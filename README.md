# Hayabusa FX (15分足版)

15分足のテクニカル指標にもとづいて為替の売買シグナル(買い / 売り / 様子見)を表示する、Expo (React Native) 製のモバイル/Webアプリです。

## 主な機能

- **通貨ペア一覧**: 10ペアそれぞれを「🟢 買い候補 / 🔴 売り候補 / 🟡 様子見 / ⛔ 取引しない / ⚠ データ確認中」の**1行1結論**で表示。上部に候補件数、停止中はその理由(後述)
- **NEXT ACTION**: ホームは「🟡 待つ / 🟢 買う / 🔴 売る / 🔵 そのまま保有 / 🔴 今すぐ決済 / ⛔ 取引しない」の1つだけを最大表示。数量・TP・SL・最大損失もその場に出します
- **通貨ペアの選択**: ホーム上部のペア名から10ペアを切り替え。ホーム・分析・一覧で共有され、保有中は切り替えられません
- **エントリー指示の保持(5分)**: 「買う / 売る」が出たあと、OANDAで注文して戻ってくる間に1分足が動いて「待つ」に戻っても、**その注文内容と「エントリーした」ボタンを5分間そのまま残します**。指示そのものは取り下げますが、実際に持ったポジションを記録できなくなると決済ナビが出ないためです(後述)
- **手動でのポジション登録**: 指示が無い時でも「すでに持っているポジションを登録する」からいつでも建玉を登録できます。アプリが知らない持ち玉を作らないための逃げ道です
- **保有時間の選択**(15分 / 1時間 / 2時間)。必要勝率は保有時間によらず40%です
- **エントリー時刻カウントダウン**: 15分足が確定する 00 / 15 / 30 / 45 分までの残り時間を秒単位で表示。残り1分を切ると色が変わり、エントリー準備の合図になります
- **総当たり探索**: 通貨ペア × 判定方針 × 判定時刻 × 厳選度 × 売買方向の全組み合わせを試し、期間を探索/検証に分けて過剰適合を弾きます(後述)
- **統計にもとづく予測**(詳細画面):
  - **判定時刻の想定レンジ**: 直近の15分足リターンの標準偏差から、約68%(±1σ)/約95%(±2σ)で収まる価格帯を算出(判定時刻が先なら√本数ぶん広がります)
  - **現在シグナルの過去成績**: 表示期間内で同じシグナルが出た全ての足について、判定時刻の足がシグナル方向へ動いたかを集計した勝率・的中数・平均変動率。損益分岐を境に色分けし、サンプルが少ない場合は警告を表示
  - 買い/売り両シグナルの勝率とサンプル数の比較
- **リアルタイム更新**: 現在値(BID/ASK/スプレッド)を**3秒ごと**に更新し、形成中の足としてチャートにも反映します
- **足の確定に合わせた自動更新**: 00 / 15 / 30 / 45 分の8秒後にローソク足を再取得します(シグナル計算には確定した足のみを使うため、判定が数秒ごとに揺れることはありません)
- **判定方針の切り替え**(自動 / 順張り / 逆張り)。選択は端末に保存され、切り替えてもAPIは再取得しません
- 各ペアの詳細画面で、15分足の価格チャート(1日 / 3日 / 5日分)とシグナル根拠を表示
- SMA(短期5本・長期20本)のクロス、RSI(14)、MACDヒストグラムを組み合わせたルールベースの売買シグナル
- Pull to refresh でウォッチリストを再取得
- Expo Web出力に対応し、スマホのブラウザからインストール不要で開けるモバイルWeb版あり

### エントリー判定の3条件

勝率は「次の足が予想方向へ動いたか」しか数えないため、**勝率が損益分岐を超えていても収支がマイナスになる**組み合わせが実際に出ます(当たった時の値幅より、外れた時の値幅が大きい場合)。これを勝率だけで見分けるのは無理なので、次の3条件をすべて満たした時だけ「条件クリア」としています。

| 条件 | 基準 | 理由 |
|---|---|---|
| 勝率 | **40%以上** | リスクリワード 1:1.5 での損益分岐 = 1 ÷ (1 + 1.5) |
| 1回あたりの期待値(コスト差引後) | **プラス** | 平均変動率 − スプレッド。方向が当たっても値幅で負ける組み合わせを弾く |
| サンプル数 | **30件以上** | これ未満は偶然と区別できない |

判定は3段階です。

| 表示 | 意味 |
|---|---|
| ○ **エントリー条件クリア** | 3条件すべて達成 |
| △ **条件は満たすがサンプル不足** | 勝率・期待値は達成、サンプルが30件未満 |
| × **エントリーしない** | 勝率または期待値が条件を満たしていない、あるいはシグナルなし |

期待値の判定には、現在値の bid/ask から求めた**往復スプレッド**を差し引いています(例: CHF/JPY で 196.32・スプレッド2銭なら約 0.010%)。現在値が取れていない場合はスプレッドを 0% として扱い、その旨を画面に表示します。

現在のシグナルが条件を満たさず、**反対方向なら満たす**場合は「このペアは『買い』なら3条件を満たします」と案内します。そのペアを切り捨てるのではなく、シグナルが切り替わるのを待つ判断ができるようにするためです。

判定はウォッチリストと詳細画面で同じ期間(既定3日)・同じ関数(`src/utils/verdict.ts` の `evaluateEntry`)を使うため、一覧と詳細で結論が食い違うことはありません。

### FX専用です(バイナリーオプションは外しました)

v2 では **FX のみ**を扱います。バイナリーは判定時刻が固定で、リアルタイムに追随する
ナビゲーション設計と噛み合わないため、画面から外しました。判定ロジック自体は
`src/utils/verdict.ts` に残してあるので、必要になれば戻せます。

**保有時間は 15分 / 1時間 / 2時間** から選べます。15分に固定する理由はありません。
スプレッドは保有時間によらず1往復ぶんしかかからないため、長く持つほど同じコストに
対して値幅が大きくなります。必要勝率は保有時間によらず 40%(リスクリワード 1:1.5)です。

### 一覧の見かた(取引していい / 様子見 / 停止)

一覧は各ペアを**1行1結論**で出します。バッジを2つ並べると結局読み合わせが要るため、1つにまとめています。

| 表示 | 意味 |
|---|---|
| 🟢 **買い候補** / 🔴 **売り候補** | 3条件がそろった。タップしてホームでトリガーを待つ |
| 🟡 **様子見** | 未成立の条件がある(理由を右に表示) |
| ⛔ **取引しない** | 口座側の停止、または上位足が逆を向いている |
| ⚠ **データ確認中** | 現在値が古い / 異常 / スプレッド拡大 |

**一覧とホームで見ている条件が違います。** 一覧は10ペアぶんを見るため、**15分足だけを取得して1時間足・4時間足を合成**し、次の3条件を判定します。

1. 市場環境(上位足がそろっているか)
2. 15分足の方向
3. 過去成績(勝率・期待値・サンプル数)

5分セットアップと**1分足のトリガーは含みません**。トリガーは数分で変わるため一覧に出しても意味が薄く、ホームで待つべきものだからです。したがって

- **一覧** = そのペアを開く価値があるか
- **ホーム** = 実際に入るか(5条件)

という役割分担になります。一覧が候補を出したペアをタップし、ホームでトリガーを待つ導線です。

**停止は全ペアに効きます。** 連敗・1日の損失上限・取引数上限に達した時、およびポジション保有中は、**全行が ⛔ 取引しない**になります。止まっている時に「買い候補」が並んでいると誤操作を招くためです。上部のバナーに理由が出ます。

配信が止まっている時も候補を出しません。価格が「存在するか」ではなく**鮮度**まで見ています(ホームと同じ `evaluateDataHealth` を使用)。

### 通貨ペアの選択

ホーム最上部のペア名を押すと10ペアから選べます。選択はホーム・分析・一覧で共有され、
端末に保存されます。**保有中は切り替えられません**(見ているペアと持っている建玉が
食い違うと事故になるため)。

**選択画面にも各ペアの判定が出ます。** 「開いてみるまで入れるか分からない」状態を避けるため、
一覧とまったく同じ判定(`src/utils/watchlistStatus.ts` の `buildPairStatus`)を各行に表示し、
上部に候補件数、停止中はその理由を出します。候補のペアは緑の枠で囲まれます。

判定に必要なレートは**選択画面を開いた時だけ**取得します(常時取得すると、使っていない
9ペアぶんまで叩き続けることになるため)。一覧を見た直後に開いた場合はキャッシュに載って
いるので追加のリクエストは発生しません。

### エントリー指示が消えたあとの記録(エントリーラッチ)

「買う」は5条件すべてが揃った瞬間だけ出ます。このうち**1分足のトリガーは最も揺れやすく**、
OANDAで注文して画面に戻ってくる1〜2分のあいだに条件が外れて「待つ」へ戻ることがあります。
この時に注文票と「エントリーした」ボタンまで消えてしまうと、**実際に持っているポジションを
アプリに登録できず、決済ナビ(そのまま保有 / 今すぐ決済)が一切出ません**。持ち玉が野放しに
なるのが一番危険なので、次のようにしています。

- 「買う / 売る」が出た時点の注文内容(方向・数量・TP・SL・エントリーゾーン・根拠)を
  **5分間だけ保持**します(`src/state/entryLatchStore.ts`、localStorage に保存するので
  リロードしても消えません)
- 指示が消えたあとは、NEXT ACTION は正直に「待つ」に戻します。**古い指示は出し続けません**。
  保持しているのは「記録する手段」であって指示ではないことを、カードの文言でも明示します
- カードからは「エントリーした」(記録に進む)と「注文していない」(取り消す)を選べます
- 期限切れ・方向の反転・停止条件(連敗/損失上限/取引数上限)に達した時は自動で取り下げます。
  **データ異常では取り下げません**(起動直後や配信が詰まった時ほど「もう注文したのに記録
  できない」が起きるため)
- 保持が切れたあとでも「すでに持っているポジションを登録する」からいつでも登録できます

**約定価格に合わせてTP/SLを計算し直します。** 記録画面で実際の約定価格を入れると、TP/SLは
その価格からの距離(ATR×1.5、RR 1:2)で引き直されます。提示価格のTP/SLをそのまま使うと、
価格が動いたあとに記録した時に**損切りが約定価格の反対側に来てしまい、登録した瞬間に
「今すぐ決済」**になります。

**建てた直後5分間は、1分足の反転では決済を出しません。** エントリーは1分足のトリガーで
入るため、直後に1分足が逆を向くのは普通のことで、これで毎回決済させると往復のコストだけが
残ります。逆行が本物なら損切り価格が拾います。**TP/SLへの到達と、15分足の転換は猶予中でも
出します**(`EXIT_GRACE_MS` / `src/utils/nextAction.ts`)。

### 条件を満たす組み合わせを探す(総当たり探索)

ウォッチリスト上部の「**条件を満たす組み合わせを探す**」から実行します。**通貨ペア × 判定方針 × 判定時刻(FXは保有時間) × 厳選度 × 売買方向**のすべての組み合わせ(10ペアなら540通り)を機械的に試し、条件を満たすものがあるかを調べます。手作業で切り替えて回るのは非現実的なので、機械にやらせるためのものです。

期間は 7日 / 14日 / 30日から選べます。**長いほどサンプルが増え、統計が効くようになります。**「サンプル不足(△)」で止まるのは3日ぶんしか見ていないからで、これが最も効く対策です。

#### 総当たりには罠が2つあるので、両方に対策を入れています

**1. 多重比較.** 540通りも試せば、優位性がまったく無くても偶然よく見えるものが必ず出ます。信頼水準を固定の95%(z = 1.96)のままにすると、これを本物として拾ってしまいます。試行回数に応じて **Šidák 補正**で水準を引き上げています(540通りなら99.995%・z ≈ 3.9)。補正後の値は結果画面に表示されます。

**2. カーブフィッティング.** 過去データに最も合う組み合わせを選ぶ行為そのものが、その期間への過剰適合です。そこで期間を **前70%(探索) / 後ろ30%(検証)** に分け、**検証区間は探索に一切使いません**。探索で通った組み合わせだけを、伏せておいた検証区間で試します。

検証区間の判定も点推定ではなく統計的に行います。勝率が損益分岐を上回って「見えた」だけでは通らず、ここでも信頼区間の下限で判定し、**生き残った件数ぶんの多重比較補正**をかけます(探索の540通りではなく、実際に検証にかけた件数で補正するのが正しい)。この補正が無いと、ランダムな値動きのデータでもFXで6件が「検証通過」として出ました。補正後は0件です。

結果は3段階で出ます。

| 表示 | 意味 |
|---|---|
| **検証でも通過** | 探索で見つかり、伏せた期間でも再現した。使う価値がある候補 |
| **探索のみ通過** | 過去に合っていただけの可能性が高い。**使わないでください** |
| **0件** | この期間・この指標では優位性が見つからなかった |

**「検証でも通過 0件」は不具合ではなく結果です。** ランダムな値動きのデータで検証したところ、探索区間では11件が通過しましたが、検証区間で残ったのは0件でした。補正と分割が意図どおり効いていることの確認です。

期間を変えて何度も試すことはできますが、**通るまで試す行為そのものが多重比較**になります。通らなかったという結果を受け入れるのが、最も損をしない選択です。

#### 正直な注意

このアプリの15分足シグナルで実測される勝率はおおむね33〜55%です。損益分岐の40%は超えうる水準ですが、**「検証でも通過」が0件のまま**ということは十分にありえます。それは不具合ではなく、その期間・その指標では優位性が見つからなかったという結果です。

本アプリはレート集計と判断材料の提示のみで、証券会社との接続も発注機能も一切ありません。実際の注文はご自身で行ってください。

### 判定方針(順張り / 逆張り / 自動)

RSI は「買われ過ぎ(70超)なら反転」という**逆張り**の指標として使われる一方、強いトレンド相場では「勢いが強い」ことを示す**順張り**のサインでもあります。同じ数値が正反対の意味を持つため、方針を選べるようにしています。

| 方針 | RSI > 70 の解釈 | 向いている相場 |
|---|---|---|
| 逆張り | 買われ過ぎ → 売り方向(−1) | 揉み合い |
| 順張り | 勢いが強い → 買い方向(+1) | 強いトレンド |
| 自動 | 効率比で判定して上記を切り替え | 全般 |

RSI が 30〜70 の範囲では順張りと逆張りの判定は完全に一致し、方針の違いは極端な水準でのみ現れます。

**自動**では Kaufman の効率比(Efficiency Ratio: 期間の正味の値動き ÷ 各足の値動きの合計、0〜1)を使い、`0.35` 以上をトレンド相場と判定して順張りに、それ未満を揉み合い相場と判定して逆張りに切り替えます。判定結果と効率比の実測値は画面上に表示されます。

逆張り単独では、一方向に伸びる強いトレンドで SMA の +1 と RSI の −1 が相殺してシグナルが出なくなる問題がありました(検証用のトレンド系列で発火 0 件)。順張り / 自動ではこれが解消されます(同じ系列で 99 件 / 98 件)。

どの方針が有効かは通貨ペアや時間帯で変わるため、方針を切り替えて**勝率の比較**ができるようになっています。統計は選択中の方針で再集計されます。

### 統計値の算出方法について

勝率は、画面表示中のシグナルと**まったく同じ判定ロジック**(`src/utils/signal.ts` の `scoreAt`)を過去の各足に適用して集計しています。表示と検証でロジックが食い違わないよう、両者は同じ関数を共有しています。

ただしこれは表示期間の過去データを集計した**過去成績**であり、将来の成績を保証するものではありません。想定レンジも価格がランダムに動くと仮定した統計的な目安で、方向性を予測するものではありません。

## データソース

**[GMOコイン「外国為替FX」の Public API](https://api.coin.z.com/fxdocs/) を使用しています（既定）。認証が不要なため、APIキーもトークンも設定不要で動作します。**

- 認証なし = **漏洩する秘密情報が存在しない**
- 口座開設も不要（Public APIのため）
- 15分足のローソク足と現在値の両方に対応
- 対応通貨ペアは10ペア（USD/JPY, EUR/JPY, GBP/JPY, AUD/JPY, NZD/JPY, CAD/JPY, CHF/JPY, EUR/USD, GBP/USD, AUD/USD）

ローソク足は日付単位で取得する仕様のため、必要な本数が揃った時点で取得を打ち切っています（10ペアで約20〜40リクエスト、同時実行は4本まで）。現在値は `ticker` が全銘柄を1リクエストで返すため、監視数によらず1回です。

現在値は3秒ごとに更新します(`ticker` は全銘柄を1リクエストで返すため、毎分20回で収まります)。

### CORSについて(重要)

**GMOのAPIはブラウザからの直接アクセスを許可していません(実機で確認済み)。** そのため次の2段構えにしています。

1. **中継サーバ経由(現在の構成)**: `gmo-proxy/` を Cloudflare Workers にデプロイ済み。ブラウザから中継サーバ経由でGMOを叩けるため、**3秒ごとのリアルタイム更新**になります
   - 稼働中: `https://hayabusa-fx-gmo-proxy.kei-047.workers.dev`
   - `.env` の `EXPO_PUBLIC_GMO_PROXY_URL` で指定
2. **フォールバック**: 中継サーバに届かない場合、GitHub Actions が公開した静的JSON(`gh-pages` の `data/`)を同一オリジンで読みます。表示は「〇分前の値」と明示されます

**中継サーバを立てる**: `gmo-proxy/` に用意しています。**このWorkerは秘密情報を一切持ちません**(GMOのPublic APIは認証不要のため)。ブラウザから直接接続できない場合はアプリが画面上にその旨と対処方法を表示するので、次の手順で中継を挟んでください。

```bash
cd gmo-proxy
npx wrangler login
npx wrangler deploy
# 表示されたURLを .env に設定
# EXPO_PUBLIC_GMO_PROXY_URL=https://your-worker.workers.dev
```

<summary>Twelve Data構成（旧）について</summary>

[Twelve Data](https://twelvedata.com/)の為替15分足API(`/time_series`)を使用します。

無料プランの上限は **8クレジット/分・800クレジット/日** です。バッチリクエストは「シンボル数 = 消費クレジット数」となるため、23ペアを一度に投げると即座に429(レート制限)になります。これを踏まえて次の対策を入れています。

- **分割取得**: 6ペアずつ・約65秒間隔で順に取得し、届いたぶんから画面に表示(最初の6ペアはすぐ表示されます)
- **キャッシュの永続化**: 取得結果は10分間 `localStorage` に保存するため、**ページを再読み込みしてもAPIを叩き直しません**。これがないと、リロードのたびにクレジットを消費して429を誘発します
- **429からの自動復帰**: レート制限に当たっても待機して自動で再試行します(最大3回)。画面には待機中である旨を表示し、エラーにはしません

1回の全体更新でペア数ぶんのクレジットを消費します。予備の80クレジットを残す設計のため、ウォッチリストの自動更新は**1日あたり31回(連続約7.8時間ぶん)**まで動き、それを超えると自動更新のみ停止します(手動更新は引き続き可能)。詳細画面の自動更新は1回1クレジットなので、1日中開いていても96クレジットで収まります。

</details>

| 業者 | 個人向けAPI | 備考 |
|---|---|---|
| **GMOコイン** | ✅ **認証不要のPublic API** | 本アプリの既定。口座不要 |
| OANDA証券 | △ 条件あり | GOLD会員 + NYサーバー残高25万円 + **プロコース**が必要。プロコースはスプレッドが倍(0.4銭→0.8銭)になる |
| デューカスコピー・ジャパン | ✅ FIX API / JForex API | Java中心 |
| 松井証券 | ❌ 事業者向けのみ | QUOREA FX等との接続用 |

証券会社のAPIトークンは**発注権限を持つ**ため、静的ページのJSに埋め込むことはできません(公開ページのJSは誰でも読めます)。OANDA構成を使う場合はトークンをサーバー側に置くプロキシが必須です(`oanda-proxy/` に実装済み)。**GMOのPublic APIは認証自体が無いため、この問題が発生しません。**

## セットアップ

APIキーの設定は不要です。

```bash
npm install
npx expo start
```

Expo Go アプリ(iOS / Android)で表示された QR コードを読み取るか、iOS シミュレータ / Android エミュレータで起動してください。

## モバイルブラウザ版(Web版)

インストール不要で、スマホの Safari / Chrome から直接使えるWeb版も用意しています。

```bash
npx expo start --web
```

表示されたURLをスマホのブラウザで開いてください。スマホ幅に最適化されたレイアウトで、PCなど広い画面で開いた場合も中央にスマホ相当の幅で表示されます。

配信用に静的ファイルを書き出す場合は以下を実行し、`dist/` を任意のホスティングサービスにアップロードしてください。既定構成では**バンドルに秘密情報が含まれません**。

```bash
npx expo export --platform web
```
